# 寰球智投 · 客户端功能与布局改进路线图

> 编写日期：2026-11-18 · 基线版本 v2.3.1 · 对标对象：东方财富 / 同花顺客户端
> 本文件是后续版本的需求基线：每完成一项，在「实施状态」里更新状态与版本号。

---

## 一、目标与边界

**目标**：在现有技术栈（零 npm 依赖、Node 单进程、原生 SPA + ECharts、免费公开行情接口、sqlite/json 双存储、本机 + NAS 双部署）不变的前提下，对标专业行情终端补齐核心功能缺口、理顺信息架构、降低单体前端维护风险。

**不做的事（合规与成本红线）**：

- 不做实盘下单、账户托管——本工具是行情与策略研究终端，不持有交易资质；
- 不接 Level-2 十档、逐笔委托、龙虎榜逐笔等付费数据；
- 北向资金不做「盘中实时净流入」（2024-08 起交易所已取消该披露，任何免费源给出的盘中数字都不可信）；
- 所有评分、筛选、预警继续标注「规则模型 / 估算口径，非投资建议」。

## 四·五、手机端核查（2026-11-19，v2.6.0）

**方法**：隔离实例（临时目录 + 随机端口）+ Edge 无头（CDP 驱动），按 390×844、DPR 2 模拟手机，注册账号后逐页截图。18 张证据图在 `docs/screenshots/mobile/`（00-login ~ 17-data-calendar，含整页长截图）。

**结论：九个一级页面 + 个股/美股详情弹窗在 390px 下均可正常显示与操作**，发现并修复 6 处问题：

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 云端预警开关在手机上完全不显示 | `@media(max-width:430px)` 里写了 `.auto-toggle{display:none}`，原本只想藏顶栏的「自动」开关，把页面里所有开关一起藏了 | 作用域收窄为 `.top-actions .auto-toggle` |
| 2 | 龙虎榜同一只股票重复出现（如九阳股份两行） | 东财一只股票可因多个「上榜原因」各占一行，前端平铺 | 服务端按代码合并、原因用「；」拼接（金额不求和，避免重复计） |
| 3 | 龙虎榜右侧「买入/卖出/成交占比/原因」被裁掉 | 9 列在 390px 必然溢出 | 手机端改固定列宽，只留 股票/涨跌幅/上榜净额/原因，原因换行且左对齐 |
| 4 | 上榜原因文字被截断成一行 | `.table .t-sub` 自带 `white-space:nowrap`，优先级压过表格级设置 | 补 `.longhu-table .t-sub{white-space:normal}` |
| 5 | 条件选股标签在窄屏折行（「涨跌幅」与「≥」分两行） | 文案是裸文本节点，CJK 可任意断行 | 文案包 `<span>` + `white-space:nowrap` |
| 6 | 财经日历 / 可转债 / 选股结果表同样右侧溢出 | 同 3 | 各自保留 3~5 列、`table-layout:fixed`、允许换行 |

另外顺手修的两个小问题：模拟交易「累计盈亏 = 0」不再标红（用中性色）；选股结果为空时不再显示孤零零的「--」徽标。

**仍存在的已知限制（不是 bug，是取舍）**：
- 手机端复杂表格选择「少列 + 换行」而不是横向滚动；想看全部列请在桌面端打开。
- PWA 只缓存壳页面与静态资源，`/api` 不缓存（行情必须新），所以离线打开只能看到框架、没有数据。
- 未做底部 Tab（3.5），导航仍是顶部横滑，九个一级页面靠横滑切换。

## 四·六、v2.7.0 交互修复与打新/席位补齐（2026-11-19）

### 1. 叠层弹窗：个股详情不再被二级抽屉顶掉

**现象**：个股详情里点「基本面 / 龙虎榜」「个股资讯」，内容出来了，但个股弹窗没了；关掉抽屉回不到个股。

**根因**：`#overlayRoot` 只允许一层。两处抽屉都调 `mountOverlay()`，而它是
`root.innerHTML = \`<div class="overlay">…</div>\``——用新内容整体替换，等于把基座弹窗销毁。

**修复**：新增 `pushOverlay(html, className)` 与 `topLayer()`：

- 上层是独立的 `.overlay-layer`（z-index 140 > 基座 130），append 到 `#overlayRoot`，不碰基座；
- `closeOverlay()` 先判断有没有 `.overlay-layer`：有就只 `remove()` 最上面那层，**不动** `state.stockModal`、不改 hash、不恢复 `body.overflow`；空栈后才执行原来的整层清理（清 hash、清 `stockModal`/`usStockModal`、恢复滚动）；
- `Escape`、点遮罩、点 `[data-close]` 都走同一个 `closeOverlay()`，所以天然逐层关闭；
- 抽屉内部的选择器改为作用域查询（`overlay.querySelector('.drawer')`、`$$('#f10Tabs button', drawer)`），避免 `$('.drawer')` 命中下层。

**「查看大盘策略」的特殊处理**：它是视图切换而不是弹窗，原本带 `data-close` → 先关弹窗再切视图。改为 `data-strategy-new` → `window.open(...#strategy)` 新标签页打开，本页个股详情保持不动；被浏览器拦截时退回原行为（关弹窗 + 本页切策略）并 toast 提示。

### 2. 自选股列表改成与自选基金同款表格

原来自选股是 `.watch-table` + `.watch-card-row` 卡片行（头像 + 若干 `watch-cell`），自选基金是 `table.fund-watch-table`，两套视觉。现在自选股直接输出
`<table class="table fund-watch-table watch-stock-table">`，**复用基金表的全部样式与响应式规则**（表头、`fund-drag-grip`、`t-name/t-code`、`fund-watch-actions` 按钮、≤780 / ≤430 两档列精简），只加一个 `watch-stock-table` 做自选股专属微调（≤780 藏「行业」、藏 ↑↓；≤430 再藏「警」）。

拖拽排序抽成 `bindWatchDrag(container)`：桌面走 HTML5 drag 事件，手机走共用的 `bindTouchReorder`（长按 420ms 进入拖拽、跟手浮标、松手重排），与自选基金同一套体验。原来绑在 `#watchTable` 上的 `.watch-card-row` 选择器已删除。

列：股票 / 最新 / 涨跌幅 / 主力净流入 / 技术评分 / 评级·仓位 / 行业 / 操作（↑ ↓ K 警 ×）。

| 项 | 数据 | 口径 |
|---|---|---|
| 新股申购 | 东财 `RPTA_APP_IPOAPPLY`（App 端「新股申购」同表） | `(APPLY_DATE>='today')` 升序；发行价/发行市盈率未定价时为 `null`，前端显示「待定」；申购上限显示「N 股」 |
| 转债申购 | 东财 `RPT_BOND_CB_LIST`（与可转债看板同源） | `(PUBLIC_START_DATE>='today')` 升序；给出申购代码（`CORRECODE`）、正股、评级、发行规模、转股价 |

**时区坑**：`new Date().toISOString().slice(0,10)` 是 UTC 日期，本地凌晨 0–8 点会算成昨天，导致当天申购的新股被过滤掉。新增 `todayText()`（`Date.now()+8h` 后取日期）专门给这两条日历用。

**为什么不用 `RPT_IPO_*`**：`RPT_IPO_INFO` / `RPT_IPO_ISSUE` / `RPT_NEWSTOCK_*` 等全部返回「报表配置不存在」；真实报表名是从 `data.eastmoney.com/newstatic/js/xg/xglist.js` 里挖出来的 `RPTA_APP_IPOAPPLY`。

### 5. 龙虎榜机构席位明细

数据：`RPT_BILLBOARD_DAILYDETAILSBUY` + `RPT_BILLBOARD_DAILYDETAILSSELL`（字段：`OPERATEDEPT_NAME / BUY / SELL / EXPLANATION`）。

处理规则：

- 买卖两张报表按「日期 + 席位名」合并成一行，净额 = 买 − 卖；
- 同一只股票同一天可能因多个上榜原因各披露一遍席位（同一份清单），按**日期**分组、原因用「；」合并，避免重复铺满屏；
- `/机构/` 标 `isOrg`、`/股通/` 标 `isNorth`，每个上榜日汇总「机构净额」；
- 买卖都为 0 的分类席位（科创板/创业板偶发）直接剔除；
- 只保留最近 12 个上榜日。

**披露口径差异**（页面上已注明）：主板披露到营业部（机构席位显示为「机构专用」），科创板/创业板有时直接披露「机构 / 中小投资者 / 其他自然人 / 沪深股通」这类投资者分类——这两类混在同一个表里时，标签比数字更重要。
